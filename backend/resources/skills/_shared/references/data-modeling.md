# SQL 与数据建模面试重点

## 业务粒度与模型
- 建模先定义事实粒度、业务主键、事件时间和可变属性，避免同一事实表混入不同粒度。
- OLTP 模型强调约束和一致性；分析模型强调扫描、聚合和可理解性，不能机械追求范式或宽表。
- 维度模型包含事实表和维度表；星型易用，雪花型减少冗余但增加关联复杂度。
- 事实可分为事务事实、周期快照和累积快照，选择取决于业务过程与分析问题。

## 维度变化与历史
- SCD Type 1 覆盖旧值，Type 2 通过有效期和版本保留历史，Type 3 仅保存有限历史属性。
- 代理键隔离业务键变化，但必须处理迟到维度、未知成员和重复映射。
- 事件时间和处理时间不能混用；时区、夏令时和业务日边界要显式定义。

## SQL 能力
- 窗口函数用于排名、累计、滑动和分组内计算，需理解 partition、order 和 frame。
- Join 前明确基数和唯一性，避免多对多关联意外放大；空值语义会影响过滤与聚合。
- 增量抽取可依据时间戳、递增键或 CDC，必须处理更新、删除、乱序和重复。
- 大查询优化关注分区裁剪、谓词下推、列裁剪、数据倾斜、Shuffle 和统计信息。

## 场景与追问
- 订单状态多次变化时，怎样同时支持当前状态和历史过程分析？
- 两张表 Join 后行数翻倍，如何定位数据问题还是 SQL 问题？
- 用户跨时区产生事件，日报口径怎样保持稳定？
- 如何设计可重跑且不会重复计数的增量模型？
