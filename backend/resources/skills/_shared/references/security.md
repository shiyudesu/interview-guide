# 应用与架构安全面试重点

## 认证、会话与授权
- 认证回答“是谁”，授权回答“能做什么”；服务端必须校验资源归属，不能依赖前端隐藏按钮。
- Session 适合服务端可撤销状态；JWT 适合跨服务传递声明，但要处理短有效期、密钥轮换、撤销和受众校验。
- OAuth 2.0 是授权框架，OIDC 在其上提供身份层；浏览器和移动端通常使用授权码加 PKCE。
- RBAC 易管理，ABAC 能表达资源和环境条件；复杂系统常组合使用并保留决策审计。

## API 攻击面
- 防越权需要在每个对象和操作上校验主体权限，避免只判断“是否登录”或相信请求中的用户 ID。
- 重放防护可结合短期时间戳、nonce、幂等键和签名；签名必须覆盖方法、路径、关键头和请求体。
- 限流按用户、租户、IP、接口成本等业务 scope 设计，代理场景下谨慎信任来源 IP。
- 文件上传需要校验实际类型、大小、压缩炸弹、文件名和解析器风险，并隔离存储与下载域名。

## Web 安全
- XSS 防护以按输出上下文编码为核心，配合 CSP、Trusted Types 和避免危险 DOM API；HttpOnly 只能降低 Cookie 被读风险。
- CSRF 利用浏览器自动携带凭证，可使用 SameSite、CSRF Token 和来源校验；Bearer Token 方案仍需防 XSS。
- CORS 是浏览器读取策略，不是服务端鉴权；不能用宽泛 Origin 加凭证解决跨域。
- SSRF 需限制协议、目标网段、DNS 重绑定和重定向，并通过受控出口访问外部资源。

## 数据与密钥
- 传输加密和静态加密解决不同威胁；敏感字段还需最小化收集、脱敏展示和访问审计。
- 密码使用专用慢哈希和独立盐，不能使用普通快速哈希；登录接口还要防账号枚举和撞库。
- Secret 不进入代码、镜像和日志，通过专用密钥系统分发，并具备轮换、吊销和最小权限。
- 日志禁止记录 Token、密码和完整隐私数据；脱敏应在统一日志入口完成。

## 供应链与工程控制
- 锁定依赖并验证来源，持续扫描已知漏洞；升级必须评估传递依赖和构建脚本风险。
- CI 凭证使用短期身份和最小权限，隔离来自不可信分支的构建，保护制品签名和发布权限。
- 安全测试覆盖静态扫描、依赖扫描、动态测试和关键权限用例，但工具结果仍需人工研判。
- 威胁建模从资产、信任边界、攻击者能力和失败影响出发，再选择控制措施。

## 场景与追问
- JWT 泄露后如何止损？为什么只缩短过期时间可能不够？
- 一个下载接口如何防止水平越权、路径穿越和响应头注入？
- 回调接口怎样同时处理伪造、重放、重复通知和密钥轮换？
- 内网 URL 抓取功能如何设计 SSRF 防线，并验证没有绕过？
