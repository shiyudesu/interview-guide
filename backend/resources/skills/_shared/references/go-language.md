# Go 语言面试重点

## 类型与数据模型
- Go 使用静态类型和结构化类型兼容；接口由方法集隐式实现，设计时优先接受小接口并在使用方定义。
- 零值应尽量可用；值接收者和指针接收者影响方法集、复制成本、可变性及接口实现。
- 字符串是只读字节序列，`rune` 表示 Unicode code point；长度、切片和遍历要区分字节与字符。
- 数组是值类型；slice 由指针、长度和容量描述，共享底层数组会带来别名和 append 后是否扩容的问题。
- map 无序且并发读写不安全；读取不存在的 key 返回零值，应使用 comma-ok 区分缺失。

## 接口、泛型与组合
- 接口值包含动态类型和值；保存带类型的 nil 指针时，接口本身不等于 nil。
- 组合优于继承，通过嵌入复用方法，但要解释名称冲突和方法提升边界。
- 泛型适合容器、算法和类型安全抽象；约束、类型集合和 `~` 底层类型决定可接受类型。
- 避免为了复用而过度泛型化；业务行为通常仍适合接口和组合。

## 错误与资源管理
- 错误是普通值，使用 `%w` 保留错误链，通过 `errors.Is/As` 判断语义，不依赖错误字符串。
- panic 用于不可继续的不变量破坏，不能替代正常错误处理；recover 只在同一 goroutine 的延迟调用中生效。
- `defer` 适合成对资源释放，但要理解参数求值时间、LIFO 顺序和循环内延迟释放问题。
- 文件、响应体、事务、计时器和 goroutine 都需要明确所有权与关闭路径。

## 包、模块与测试
- 包名、导出规则、`internal`、`init` 和依赖方向影响可维护性；避免全局可变状态和隐式初始化副作用。
- Go Modules 关注最小版本选择、语义导入版本、代理与校验数据库，以及私有模块配置。
- 表驱动测试适合覆盖输入组合；接口和函数参数可建立小型 fake，避免为测试制造庞大抽象。

## 场景与追问
- slice 作为参数传入函数后 append，调用方为什么有时能看到修改、有时看不到？
- 一个接口变量打印为 nil 指针却不等于 nil，底层发生了什么？
- 如何设计可判断、可包装且不泄露内部实现的业务错误？
- 泛型、接口和代码生成分别适合解决什么问题？
