# CSS 面试重点（布局、层叠、响应式与工程实践）

## 层叠与选择器
- 层叠结果由来源、重要性、层叠层、优先级和源码顺序共同决定；`!important` 不是常规架构手段。
- 优先级比较关注 ID、类/属性/伪类、元素/伪元素；`:where()` 的优先级为零，`:is()` 取参数最高值。
- 继承适合字体、颜色等文本属性；盒模型、定位和布局属性通常不继承。
- CSS Modules、BEM、utility-first 和 CSS-in-JS 的取舍应落到隔离、运行时成本、主题和团队协作。

## 盒模型与格式化上下文
- `content-box` 与 `border-box` 的宽高计算不同，工程中常全局使用 `border-box`。
- margin 合并只发生在特定块级流场景；BFC 可隔离浮动、阻止部分外边距合并并包含浮动元素。
- `display: none` 不占布局且通常不参与可访问树；`visibility: hidden` 保留布局；`opacity: 0` 仍可能响应事件。
- 包含块决定百分比尺寸和绝对定位基准；`transform` 等属性可能创建新的包含块或层叠上下文。

## Flex、Grid 与定位
- Flex 是一维布局，重点解释主轴/交叉轴、flex-basis、收缩计算和 `min-width: auto` 的影响。
- Grid 是二维布局，适合显式行列、区域布局和响应式卡片；关注 `fr`、`minmax()`、隐式网格。
- 绝对定位脱离普通流；`position: sticky` 受滚动容器、阈值和祖先 overflow 影响。
- `z-index` 只在相应层叠上下文内比较，不能用无限增大数值跨越父级上下文。

## 响应式与现代 CSS
- 移动优先结合媒体查询、容器查询、流式尺寸和响应式图片，而不是按具体设备型号硬编码。
- `clamp()` 可表达有上下限的流式字号；逻辑属性支持不同书写方向。
- 容器查询按组件可用空间响应，适合可复用组件；媒体查询按视口或设备特征响应。
- 深色模式同时考虑系统偏好、用户设置、持久化和首次渲染闪烁。

## 动画与渲染性能
- 修改布局属性可能触发布局和绘制；`transform`、`opacity` 通常更容易交给合成阶段处理。
- 动画应避免无界创建合成层；`will-change` 只在明确热点短期使用。
- 批量读取和写入布局属性，避免读写交错导致强制同步布局。
- 尊重 `prefers-reduced-motion`，动画不能成为理解内容或完成操作的唯一方式。

## 场景与追问
- 实现未知高度的水平垂直居中，并解释不同方案的限制。
- 长文本、国际化和动态字号下，卡片布局为什么会溢出？如何验证？
- 一个浮层被其他元素遮挡，如何沿层叠上下文定位原因？
- 页面滚动卡顿时，如何区分布局、绘制、合成和 JavaScript 问题？
