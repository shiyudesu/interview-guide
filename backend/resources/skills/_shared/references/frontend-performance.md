# 前端性能面试重点（体验指标、加载、渲染与监控）

## 指标与测量
- Core Web Vitals 关注 LCP、INP、CLS；同时观察 TTFB、FCP、资源时序、长任务和错误率。
- 实验室数据适合稳定复现，真实用户监控反映设备、网络和地域差异，两者需要结合。
- 优化前先建立基线、分位数和业务分组，不能只拿平均值或单次 Lighthouse 分数判断效果。
- 性能预算可约束 JavaScript 体积、图片体积、主线程时间和关键指标回退。

## 网络与资源加载
- 缓存策略区分 HTML、带内容哈希的静态资源和 API；明确强缓存、协商缓存与 CDN 回源。
- 关键资源可使用 preload 或提高优先级，非关键资源延迟加载，但误用预加载会争抢带宽。
- 图片按展示尺寸选择格式和分辨率，使用 `srcset`/`sizes`，同时预留尺寸减少布局偏移。
- HTTP/2 多路复用不等于可以无限拆包；请求优先级、连接复用和第三方域名仍有成本。

## JavaScript 与主线程
- 大包影响下载、解析、编译和执行；用 bundle analyzer、coverage 和性能录制定位实际成本。
- 长任务应拆分、调度或迁移到 Worker；输入响应链路要减少同步计算和无意义重渲染。
- 防抖适合等待输入稳定，节流适合限制连续事件频率；两者都要处理取消和组件卸载。
- 内存泄漏常来自未释放监听器、定时器、闭包、缓存和脱离 DOM，需要用堆快照验证引用链。

## 渲染与框架性能
- 避免布局抖动：先批量读取，再批量写入；大型列表使用虚拟化并关注动态高度和可访问性。
- React 优化先减少状态影响范围，再考虑 memo；错误依赖和不稳定引用会让缓存失效。
- Vue 优化关注响应式依赖范围、稳定 props、列表 key、静态提升和不必要的深层监听。
- SSR 可改善首屏内容出现时间，但 hydration、服务器耗时和客户端重复工作也可能成为瓶颈。

## 稳定性与第三方脚本
- 第三方统计、广告和客服脚本要设置加载优先级、超时、隔离和降级，持续监控其长任务占比。
- 弱网和低端机验证应覆盖超时、重试、离线提示、骨架屏以及操作是否可恢复。
- 前端错误应关联版本、路由、用户操作和网络请求，并设置采样、脱敏和告警聚合。

## 场景与追问
- LCP 变差但接口耗时不变，如何继续拆解资源、渲染和主线程耗时？
- INP 只在低端 Android 设备异常，如何复现并验证优化？
- 列表滚动时掉帧，如何判断是 React 更新、布局、绘制还是图片解码？
- 优化后实验室指标提升但业务转化下降，应如何分析和回滚？
