# 数据质量与治理面试重点

## 质量维度
- 完整性、唯一性、准确性、一致性、及时性和有效性需要转化为可计算规则与责任人。
- 质量规则分为 Schema、字段、跨表、业务总量和时序异常，阈值应结合历史波动而非统一常量。
- 上游成功不代表数据正确，应同时校验输入、处理中间结果和最终业务指标。
- 告警要包含影响数据集、分区、规则、样例和处置入口，避免只发送“任务失败”。

## 元数据、血缘与契约
- 技术元数据描述 Schema、分区和任务，业务元数据描述口径、负责人和使用场景。
- 字段级血缘用于影响分析和根因定位，但动态 SQL、临时表和外部脚本会降低自动解析完整度。
- 数据契约明确字段、兼容规则、质量目标和变更通知，不能仅依赖消费者自行适配。
- Schema Registry 或版本化接口帮助控制演进，但删除、改类型和语义变化仍需迁移窗口。

## 权限与生命周期
- 按最小权限控制数据集、字段和行级访问，敏感数据要分类、脱敏、审计并限制导出。
- 数据保留、删除和归档应贯穿副本、缓存、离线表、备份及下游交付。
- 测试数据不能直接复制生产敏感信息，需要生成、掩码或隔离授权。

## 场景与追问
- 上游新增枚举值导致下游指标异常，数据契约应如何提前发现？
- 数据质量告警每天大量误报，怎样调整规则又不掩盖真实问题？
- 如何证明一张核心报表的数据可以追溯到原始事件和代码版本？
- 用户要求删除个人数据时，如何确认所有数据层和导出副本都已处理？
