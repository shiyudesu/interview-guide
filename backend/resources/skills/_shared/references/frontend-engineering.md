# 前端工程化面试重点（构建、依赖、测试与发布）

## 模块与构建链路
- ESM 可静态分析，支持 tree-shaking；CommonJS 在运行时加载，混用时需解释默认导出和互操作边界。
- 开发服务器关注冷启动、按需转换和 HMR；生产构建关注代码分割、压缩、缓存和兼容目标。
- loader/transform 处理单个资源，plugin 介入完整生命周期；能说明 Vite、Rollup、Webpack 的职责边界。
- tree-shaking 依赖静态结构和副作用声明；错误的 `sideEffects` 配置可能删掉样式或初始化逻辑。

## 包管理与依赖治理
- 锁文件保证依赖图可复现；CI 应使用 frozen/immutable 安装并阻止锁文件漂移。
- `dependencies`、`devDependencies`、`peerDependencies` 的发布语义不同，组件库尤其需要正确声明 peer。
- 解释幽灵依赖、重复版本、依赖提升和供应链风险；升级需结合变更日志、测试和灰度。
- Monorepo 关注任务缓存、受影响项目计算、版本策略、边界约束和共享配置，而不只是目录合并。

## 代码拆分与运行时交付
- 按路由、业务模块或重型依赖拆包，避免碎片过多导致请求和调度开销反升。
- 动态导入需要加载态、失败态、超时和重试设计；资源 URL 与 CDN 缓存策略必须配套。
- 微前端需回答样式隔离、运行时隔离、依赖共享、路由协调、通信契约和独立发布失败处理。
- SSR/SSG/CSR 的选择取决于内容时效、个性化、SEO、缓存能力和服务器成本。

## 测试策略
- 单元测试覆盖纯逻辑，组件测试关注用户可见行为，E2E 只保留关键业务链路。
- 避免过度断言实现细节；网络、时间和随机性应可控，测试数据需要隔离与清理。
- 合约测试防止前后端接口漂移；视觉回归适合设计系统和高价值页面。
- 不稳定测试要记录失败率、隔离根因，不能靠无限重试伪装通过。

## CI/CD 与发布
- 流水线通常包含格式、类型、单测、构建、依赖安全、E2E 和产物完整性检查。
- 静态资源采用内容哈希和长期缓存，HTML 短缓存；发布必须处理新旧资源并存和回滚。
- 灰度、特性开关和错误预算控制发布风险；Source Map 上传后应限制公开访问。
- 构建产物应可追溯到提交、依赖锁和构建环境，避免服务器现场安装依赖。

## 场景与追问
- 本地开发正常但 CI 构建失败，如何从环境、锁文件、大小写和缓存逐层排查？
- 首包突然增加 40%，如何定位由哪个依赖和哪个入口引入？
- 多团队共享组件库时，如何设计兼容策略和弃用流程？
- 前端发布后出现白屏，怎样止损、定位、回滚并验证恢复？
