# 数据仓库面试重点

## 分层与口径
- 常见分层包括原始、明细、汇总和应用层，目的在于隔离变化、复用公共逻辑并统一指标口径。
- 分层不是越多越好；每层应有清晰输入输出、粒度、负责人和生命周期。
- 指标需明确业务定义、统计周期、去重规则、维度范围和修订策略，避免同名不同义。
- 公共维度和一致性维度减少跨主题分析冲突，但需要版本和变更治理。

## 存储与计算布局
- 分区通常按高频过滤和生命周期字段设计；分桶、排序、聚簇用于减少扫描和 Shuffle。
- 小文件治理包括写入合并、定期 compact 和合理并行度，不能只增加 NameNode 或元数据容量。
- 列式格式适合分析扫描和压缩；Schema 演进需处理新增、删除、类型变化及旧文件兼容。
- 湖仓表格式通过元数据和快照支持事务、时间旅行与增量读取，同时带来维护和版本兼容成本。

## 数据服务与成本
- 离线报表、交互分析和在线特征对延迟与并发要求不同，应选择不同查询与缓存层。
- 预计算提高查询速度但增加存储和口径维护成本；即席查询灵活但需资源隔离。
- 成本治理关注扫描量、Shuffle、文件布局、保留周期、空闲资源和重复数据集。

## 场景与追问
- 同一 GMV 指标在两个报表中不一致，如何定位并建立长期治理？
- 事实表粒度选错后会造成哪些重复计算和 Join 问题？
- 湖仓表出现大量小文件，写入、查询和维护分别如何优化？
- 如何支持历史口径修订，同时保证旧报告可解释？
