# 云平台与基础设施即代码面试重点

## 云架构基础
- 高可用设计区分实例、可用区和地域故障域；跨地域部署还要考虑延迟、数据一致性和合规。
- 负载均衡、自动伸缩、托管数据库、对象存储和消息服务各自有容量、配额和故障边界。
- 云上弹性不是无限容量，应了解实例启动时间、服务配额、热点数据和下游瓶颈。
- 成本治理关注标签、预算、闲置资源、数据传输、存储生命周期和峰值容量，而不只比较单价。

## Terraform 与状态
- 声明式配置描述期望状态，plan 展示差异，apply 收敛资源；代码变更和实际漂移要分别处理。
- State 包含资源映射和可能的敏感数据，需要远端加密、锁、备份、权限隔离和恢复方案。
- Module 应提供稳定输入输出和版本约束，避免把组织全部基础设施塞进一个巨大状态文件。
- 导入存量资源后要验证配置与真实属性一致；手工改云资源会造成 drift，不能长期依赖 refresh 掩盖。

## 权限、网络与密钥
- IAM 使用最小权限、短期身份和职责分离；禁止长期 Access Key 在开发机和 CI 中扩散。
- VPC 子网、路由、安全组、网络 ACL 和私网出口解决不同层面的问题。
- KMS 管理密钥生命周期和审计，应用 Secret 仍需轮换、版本化和最小可见范围。
- 多账号/多项目隔离生产与非生产，集中审计但避免共享高权限凭证。

## 变更与恢复
- 基础设施变更也需要评审、测试、分阶段发布和回滚；删除或替换资源要特别审查执行计划。
- Provider 升级可能改变默认值和资源行为，应固定版本并阅读升级说明。
- 灾备不能只复制配置，还需验证数据备份、DNS、证书、密钥和外部依赖的恢复顺序。

## 场景与追问
- Terraform State 丢失或锁死时如何处置，哪些操作不能贸然执行？
- 一个区域故障后服务为什么没有按设计切换？如何组织演练？
- 云账单突然增加，如何定位资源、流量、日志和数据传输成本？
- 如何让 CI 在不保存长期云密钥的情况下完成生产部署？
