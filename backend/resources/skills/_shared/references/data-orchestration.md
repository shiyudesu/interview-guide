# 数据任务调度与编排面试重点

## DAG 与依赖
- DAG 描述任务依赖而不是业务数据天然正确；依赖粒度应与数据分区和可恢复边界一致。
- 任务需声明输入、输出、执行日期、资源和 SLA，避免通过共享临时目录形成隐式依赖。
- 动态任务生成要限制规模并保持可观察，否则调度器解析和元数据库会成为瓶颈。
- 跨工作流依赖应使用数据就绪事件或明确契约，避免固定 sleep 和脆弱时间偏移。

## 幂等、重试与回填
- 重试只适合可重入任务；写入使用分区覆盖、事务提交、幂等键或临时表切换。
- 指数退避和抖动减少依赖恢复时的重试风暴，重试上限后进入明确失败和人工处置流程。
- Backfill 需要固定参数和代码版本、限制并发、隔离资源，并避免覆盖已经修订的数据。
- 补数和重跑应记录原因、范围、操作者和结果校验，不能绕过正常质量规则。

## 调度器可靠性
- Scheduler、Worker 和元数据库分别有不同故障模式；高可用调度不能产生同一任务的重复主控。
- 心跳、租约和孤儿任务回收用于处理 Worker 崩溃，恢复后仍需保证任务输出幂等。
- 优先级、队列、资源池和并发上限用于保护关键 SLA，防止低优先级回填占满集群。
- SLA miss 应关联上游延迟、排队时间、执行时间和下游影响，而不是只有最终超时告警。

## 场景与追问
- 每日任务失败后重跑导致指标翻倍，如何重新设计提交协议？
- 上游分区晚到两小时，下游 DAG 是等待、降级还是先产出后修订？
- 调度器恢复后同一任务被两个 Worker 执行，如何避免重复结果？
- 大规模历史回填与日常任务争抢资源时，如何分池和限速？
